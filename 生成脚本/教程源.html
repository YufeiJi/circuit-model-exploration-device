1　这个装置是做什么的

1.1　要解决的问题

给一个未知的模拟网络（电阻、电感、电容搭成的低通、高通、带通、带阻四种之一），要在不拆开、不查手册的前提下，测出它的类型、特征频率 f0、品质因数 Q、直流增益 K。传统做法是信号发生器加示波器，逐点扫频、手工记录、事后拟合，一个网络要半小时以上。

本装置把这三件事集成到一块 STM32F407 上：自己产生正弦激励、自己采集输出、自己拟合模型。串口发一条 L，0.5 到 0.8 秒后直接把四个参数打印出来。

3.2　三档接法

按目的分三档，不要一次全接上。每加一档只引入一个新变量，出问题时原因一定在刚加的那一环。

表 3-2　三档接线
档位接线能做什么
A 档PA2→RXD、PA3→TXD、GND→GND看串口、发命令。PA4 / PA0 空着，此时 M 测到的是噪声，正常
B 档A 档 + 示波器探头接 PA4、地夹接 GND看激励波形，验证 DAC 与定时器

只想验证测量链路本身，可以跳过网络：一根线把 PA4 直接接 PA0，这就是回环测试。

3.3　三条铁律

第一，必须共地。板子 GND、USB-TTL 的 GND、示波器地夹、被测电路地，全部连在一起。只连信号不连地，串口必然乱码，示波器上是一条 50 Hz 粗带。

第二，PA0 只能吃 0～3.3 V。ADC 的绝对最大输入是 3.6 V。已知模型的增益是 5 倍，如果激励设成 1 Vpp 再接到它输入端，输出就是 5 Vpp，直接灌进 PA0，输入保护二极管当场击穿。

第三，断电接线。所有杜邦线在断电状态下插好再上电。带电插拔时公针抖动会在瞬间产生几伏感应尖峰。

3.5　DFU 接法（推荐，已实测）

STM32F407 出厂自带一段 ROM bootloader。上电时它检查 BOOT0 电平：为 0 从 Flash 跑用户程序，为 1 则把自己变成一个 USB 设备等电脑灌数据。所以「进 DFU」就是把 BOOT0 拉高再复位。

操作顺序不能换：

  1. 拔掉 Type-C（断电）
  2. 用杜邦线把 BT0 针接到旁边的 3V3
  3. 插上 Type-C
  4. 按一下复位键 NRST

成功标志：设备管理器里出现 STM32 BOOTLOADER，硬件 ID 为 USB\VID_0483&PID_DF11。

顺带一个判据：如果插上 Type-C 后「此电脑」里多出两个打不开的盘（E: 和 F:），那不是 DFU，是出厂演示固件在跑——它把板载 2 MB SPI Flash 和 TF 卡座挂成了两个盘。此时 BOOT0 还没拉高，或者拉高后没按复位。

4　软件准备

4.1　Keil MDK

需要 Keil µVision 5，编译器用 ARM Compiler 6（AC6）。工程里已配好 AC6，若你的 Keil 只带 AC5，需在 Options for Target → Target → ARM Compiler 里切到 AC6。

4.2　器件包（只有建新工程才需要）

µVision 本体只带编译器与 CMSIS 内核头，不含任何厂商器件支持。要新建工程，必须装 ST 的器件包 Keil.STM32F4xx_DFP 2.17.0。

不要装 3.x 版本。从 3.0.0 起 ST 为配合 CMSIS-Toolbox 重构了包结构，删掉了 CMSIS Drivers、器件头文件和启动文件，只剩 Flash 算法和 SVD。裸机工程需要那些文件，装 3.x 等于没装。

安装包在本项目 工具\Keil.STM32F4xx_DFP.2.17.0.pack（276 MB），双击即可，Keil 会自动识别。

本工程不需要它也能编译。器件头 stm32f4xx.h、stm32f407xx.h、内核头 core_cm4.h 等、启动文件 startup_stm32f407xx.s 全部已 vendor 到 Keil\Drivers\CMSIS\ 下，不依赖 RTE。只有「从零新建工程」这一种场景才需要器件包。

4.3　串口驱动

插上 USB-TTL 后，设备管理器「端口（COM 和 LPT）」下应出现 USB-SERIAL CH340 (COMx)。没有就装对应芯片的驱动（CH340 驱动很小，随模块卖家一般会给）。

4.4　烧录驱动（走 DFU 才需要）

Windows 默认不给 DFU 设备装可用驱动，Python 或任何工具都访问不到它。用 Zadig 绑一个通用 WinUSB 驱动，只需做一次：

  1. 先让板子进 DFU（见 3.5），设备管理器里出现带感叹号的 STM32 BOOTLOADER
  2. 下载 Zadig：https://zadig.akeo.ie/（单文件 exe，免安装；仓库不附带，从官网取）。打开后菜单 Options 勾上 List All Devices
  3. 下拉框里只认 USB ID 为 0483 DF11 的那一条
  4. 右侧驱动框选 WinUSB，点 Install Driver，等到底部显示 Driver Installation: SUCCESS
认错设备的代价很大。Zadig 只看 VID:PID，名字里带 DFU 它不会帮你分辨。曾经误把某个摄像头（3277:0096 Camera DFU Device）的驱动换掉，导致摄像头失效。回滚方法：设备管理器里右键该设备 → 卸载设备 → 勾上「尝试删除此设备的驱动程序」 → 卸载 → 扫描检测硬件改动。

5　编译

5.1　打开工程

双击 Keil\CircuitModel.uvprojx。工程自带全部头文件与启动文件，不勾任何 RTE 组件。

5.2　编译

按 F7（Build）。第一次编译约 3 秒，之后增量编译 1 秒。

5.3　检查产物

成功的日志末尾应该长这样：

linking...
Program Size: Code=17324 RO-data=1404 RW-data=28 ZI-data=18532
FromELF: creating hex file...
".\Objects\CircuitModel.axf" - 0 Error(s), 0 Warning(s).

把这四个数换算一下：

ROM = 17324 + 1404 + 28 = 18756 B ≈ 18.3 KB   （512 KB 的 3.6%）
RAM = 28 + 18532      = 18560 B ≈ 18.1 KB   （128 KB 的 14.1%）

ZI-data 18532 B 的构成是合理的：DDS 正弦表 2048 B、ADC 采样缓冲 2048 B、栈 4096 B，其余是各模块静态缓冲与字符串字面量。

再确认 hex 文件本身没写错地址：用记事本打开 Objects\CircuitModel.hex，看三处。

6　烧录

两条路，任选其一。DFU 只用一根 Type-C 线，不需要额外硬件，是本项目的默认路线；ST-Link 适合想要在线调试的场合。

6.1　路线 A：USB DFU（已实测通过）

第一步　进 DFU

见 3.5：断电 → BT0 接 3V3 → 插 Type-C → 按 NRST。设备管理器出现 STM32 BOOTLOADER。

第二步　装驱动（只需一次）

见 4.4：Zadig 选 0483 DF11 → Install Driver。

第三步　烧录

双击 工具\调试台\启动调试台.bat，切到「DFU 烧录」页：点「连接 DFU 设备」，把 Keil\Objects\CircuitModel.hex 拖进虚线框，再点「开始烧录」。日志会是这样：

[15:12:43] —— 开始烧录 ——
[15:12:43] 状态机 dfuIDLE，可以开始。
[15:12:43] 擦除：擦除扇区 0x08000000（16.0 KB）、0x08004000（16.0 KB）
[15:12:44] 擦除完成，共 2 个扇区。
[15:12:44] 写入：
[15:12:45] 烧录完成：18752 字节，2.0 秒（9.2 KB/s）

换成别的 hex 直接拖另一个文件进去，不需要改任何路径。

工具是在浏览器里直接实现 DFU 1.1 与 ST 的 DfuSe 扩展，不依赖 CubeProgrammer，也不需要 ST 账号。协议细节与踩过的坑写在 工具\调试台\README.md 里。

第四步　退出 DFU

这一步最容易忘，忘了会以为固件坏了。断电 → 把 BOOT0 从 3V3 挪回 GND → 插上 Type-C → 按 NRST。BOOT0 还挂在 3V3 的话，芯片会一直停在 bootloader 里，你的程序根本不跑，串口一片安静。

6.2　路线 B：ST-Link SWD

接线见 3.4。然后在 Keil 里配置两处：

  1. Debug 页：下拉框选 ST-Link Debugger，勾 Load Application at Startup 与 Run to main()。点 Settings，Port 选 SW，Max Clock 建议 1.8 MHz（克隆版在 4 MHz 下常报 RDDI-DAP Error）。
  2. Flash Download 页：列表里应有 STM32F4xx 512kB Flash Start: 0x08000000 Size: 0x80000。空白就点 Add，选 ARM\Flash\STM32F4xx_512.FLM（本项目 工具\ 与 Keil\Flash\ 各存了一份）。勾上 Erase Sectors、Program、Verify、Reset and Run。

之后按 F8 下载，日志出现 Verify OK 与 Application running 即成功。

6.3　烧完必做

不管走哪条路，烧完都要确认三件事：

  1. BOOT0 回到 GND
  2. 按一次 NRST
  3. 串口助手以 115200 8N1 打开，能看到启动横幅

7　上电自检

7.1　串口横幅

复位后应立刻打出三行：

==== Circuit Model Explorer (STM32F407VET6, bare-metal) ====
SYSCLK = 168000000 Hz, DAC fs = 1000000 SPS, ADC fs = 500000 SPS, N = 4096
Ready. Type ? for help.

这三行信息量很大：168000000 说明 PLL 锁定、时钟树配置正确；1000000 说明 TIM6 分频对；500000 说明 TIM3 分频对；4096 说明采集点数对。四个数任何一个不对，后面的测量都不必做。

7.2　没有串口时的自检

用万用表直流电压档量 PA4 对 GND。程序默认输出 1 kHz / 1.0 Vpp 正弦，直流档读到的是它的平均值，也就是偏置电压，应在 1.65 V 左右。

读到 1.65 V 说明：程序在跑、时钟正确、DAC 在工作、DMA 在搬运。这一步不需要串口也不需要示波器。

7.3　串口没输出怎么查

8　五级测试

一层一层往上搭，每级只引入一个新变量。出问题时原因一定在刚引入的那一环，这样排查范围永远只有一处。

L1　串口握手

发 H 应得到：

|H(1000.0 Hz)| = 2.5257 (8.05 dB)

这个数不是随便写的，是已知模型在 1 kHz 处的理论增益：H(s) = 5 / (1e-8·s² + 3e-4·s + 1)，代入 ω = 2π·1000 算得 |H| = 2.5257。它同时验证了浮点单元、数学库、printf 重定向三条链路。

L2　激励波形（可选）

示波器设 DC 耦合、1 V/div。应看到 1 kHz 正弦、2.0 Vpp、中心约 1.65 V。

波形呈阶梯状是正常的。DAC 以 1 MSPS 更新，1 kHz 时一个周期只有 1000 个点，放大就能看到台阶。把频率拉到 F50000 台阶会更明显（一周期 20 点），降到 F100 则很平滑。

L3　ADC 回环

一根杜邦线把 PA4 直接接到 PA0。依次发：

F1000
A1.0
M

应得到：

Vout = 1.0000 Vpp, phase = -1.3 deg

幅度误差应小于 3%。相位在直连时理论为 0，实测几度以内都正常，来自 DAC 与 ADC 采样时刻的固定偏差。

想更严一点，换几个频点各测一次，幅度都应稳定在 1.0 Vpp 附近：

F500  /  F2000  /  F5000  /  F10000
低频别低于 300 Hz。ADC 采集窗只有 8.192 ms，100 Hz 时不足一个完整周期，测不准是原理限制，不是故障。

L4　开环控制

接上已知模型电路（见附录 B）：PA4 → 网络输入，网络输出 → PA0，网络地 → GND。

先降幅再接线。已知模型增益 5 倍，1 Vpp 进去就是 5 Vpp 出来。先发 A0.3 把激励降到 0.3 Vpp，再接上线。

然后发：

F1000
C1.0

应得到：

target 1.000 -> Vin 0.396 -> Vout 1.000 Vpp (err 1.85%)

固件按 1 kHz 处 |H| = 2.5257 反算出需要的输入幅度 0.396 Vpp，设好之后再实测一次，把误差打出来。误差绝对值小于 5% 算通过。

若误差在 5% 到 10% 之间，做一次校准：用实测 Vout 除以 2.5257 得到实际增益比，发 K<比值>（例如 K1.032），再跑一次 C1.0。

L5　未知模型辨识

换成待测的 RLC 网络，发：

L

约 0.5 到 0.8 秒后输出：

type = Low-pass
K = 1.002, f0 = 1590.3 Hz, Q = 0.3341, err = 0.00812

它扫 26 个频点（200 Hz 到 100 kHz），把低通、高通、带通、带阻四种二阶模型分别拟合，取对数域残差最小的那一个。

为什么不靠找峰值判类型。本题元件范围（R 1～10 kΩ、L 1～10 mH、C 10～100 nF）推出的 Q 在 0.01 到 1 之间。Q ≤ 1 时带通曲线根本没有谐振峰，靠形状判据在原理上就不成立。所以用拟合残差，四个模型各拟一次，谁最像就是谁。

判据：

  • 类型判断正确
  • f0 相对误差小于 10%
  • 拟合残差 err 小于 0.05

err 偏大通常说明网络里有寄生参数（电感绕线电阻、电容 ESL），或者元件标称值与实际值差得远。用万用表量一下电阻、用电桥量一下电感，再对照结果。

附录 B　已知模型电路

传递函数 H(s) = 5 / (1×10-8·s² + 3×10-4·s + 1)，即 K = 5、ωn = 104 rad/s（fn = 1591.5 Hz）、Q = 1/3。这是一个过阻尼二阶低通，两个实极点分别在 607.9 Hz 与 4166.6 Hz，所以幅频曲线单调下降、没有谐振峰。

拓扑是「单位增益 Sallen-Key 低通」串「同相放大 ×5」两级。这样做是为了把 Q 和增益解耦：Sallen-Key 那级只负责极点位置（Q = 1/3 由电阻比决定），增益单独由后级给。

电容必须是 C0G，不能用 X7R。X7R 的容值随电压和温度能漂 ±15%，幅频误差会从 1% 级劣化到 15% 级，直接判不合格。买的时候认准 C0G / NP0 字样。
